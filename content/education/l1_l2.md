# L1 and L2

**L1** is a base settlement layer. **L2** scales execution while anchoring security (data and/or proofs) to an L1.

## Common L2 families
- Optimistic rollups (fraud proofs / challenge windows)
- ZK / validity rollups (validity proofs)
- Validiums / other data-availability tradeoffs (different trust assumptions)

## Diligence
1. What is posted to L1 — full data, commitments, or nothing?
2. Who can upgrade the bridge/contracts? Timelock?
3. Exit windows and censorship resistance assumptions
4. Sequencer centralization today vs roadmap — label ANALYSIS vs FACT

## Warnings
- “Ethereum security” marketing is not automatic; read the actual trust model.
- Bridging to an L2 inherits bridge + L2 operator risks.
- DEMO market rows are not live L2 fee quotes.
